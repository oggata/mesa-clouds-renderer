24時間配信している街のシミュレーション（[MESA](https://github.com/oggata/mesa-clouds-renderer)）で、住民の「いま何をするか」の決め方を作り直しました。

これまでの住民は、**行動の一覧から、優先順位の段（if-else）で1つ選んで**いました。

```
病気         → 病院へ
夜 or 限界   → 帰って寝る
空腹         → 飲食店へ
勤務時間     → 職場へ
日用品切れ   → 買い物
退屈         → 娯楽施設へ
どれでもない → ぶらぶら
```

わかりやすいのですが、**一覧に書いていない過ごし方は、住民には絶対にできません**。そして前回の記事で「時代」を入れたとき、スマホ時代の通販や AI 時代の在宅勤務を、「スマホ時代は70%が通販派」「AI時代は80%が在宅勤務」という**規則**として書くしかありませんでした。住民が自分で選んだのではなく、私が割合を決めていたのです。

そこで考えたのが、**RGB** です。

カラーコードは `255,255,255` の3チャンネルしかありませんが、無限の色を表せます。住民の行動も同じように、少数のチャンネルの強さの組として表せば、「一覧から選ぶ」ように見えて、実は無限の行動をとれるのではないか。

この記事は、それを実装した記録です。チャンネルをどう作ったか（因子分析）、規則を書かずに在宅勤務や通販が生まれたこと、そして解けていない問題（来店が半分に落ちた）まで、実測値つきで書きます。

## 行動をラベルからベクトルへ

「eat-ramen」のようなラベルをやめて、行動をチャンネルの強さの組で表します。

```
住民の「したいこと」 d = [満腹 0.8, 休息 0.2, 人と会う 0.6, 自然 0.4, …]
場所の「できること」 A = [満腹 0.9, 人と会う 0.2, …]            (ラーメン屋)
```

ポイントは、**場所の側も同じチャンネルで「何を与えてくれるか」を持つ**ことです。どこへ行くかは照合で決めます。

```
選ぶ場所 = argmax  Σ_c w_c · d_c · A_c − 移動の手間 + 行きつけ + 揺らぎ
```

```js
// vec.js
function match(d, cands, opt) {
  let best = null, bestS = -Infinity;
  for (const k of cands) {
    let s = 0;
    for (let c = 0; c < NC; c++) s += CH[c].w * d[c] * k.A[c];   // 欲求 × 提供
    s -= TRAVEL_W * k.dist * (0.6 + (opt.fatigue || 0));          // 疲れているほど遠くへ行かない
    s += (k.fam || 0) + (k.jit || 0);                              // 行きつけ・その日の気分
    if (k.key === opt.current) s += STICK;                         // 行ったり来たりを防ぐ
    if (s > bestS) { bestS = s; best = k; }
  }
  return best;
}
```

名前は、**選んだ後に付けます**。効いたチャンネルの上位2つと場所から組み立てます。

```
🌳 公園で体を動かす (誰かと一緒に)
☕ カフェで人と過ごす (ひと休みしながら)
自宅で連絡を取り合う (新しい発見を探して)
```

どれも一覧には書いていない過ごし方です。1日に出る過ごし方の種類を数えると、**段の版は最大8種類（Option の数）、ベクトル版は平均59.5種類**になりました。

## 前提: 犬の散歩と動物園は近いか

作る前に、チャンネルについて1つ確かめておきたいことがありました。「ベクトルで表すと、犬の散歩と動物園は近いのか？」

最初に考えた8チャンネル（満腹・休息・人と会う・静けさ・新しさ・節約・遠出・長さ）で表すと、こうなります。

```
             満腹 休息 人と会う 静けさ 新しさ 節約 遠出 長さ
犬の散歩     0.0  0.4   0.3     0.5    0.1   0.9  0.2  0.3
動物園       0.2  0.2   0.6     0.2    0.8   0.2  0.8  0.9
```

コサイン類似度は0.54で、「わりと違う行動」です。損得で見ると確かに別物です。犬の散歩は近場でお金をかけず短く、動物園は遠くまでお金を払って半日かけます。

でも人間は「どちらも動物と触れ合う」と感じます。**このチャンネルには「生き物」が無いので、その近さが見えない**のです。「生き物」のチャンネルを足す（犬の散歩0.9、動物園1.0）と、類似度は0.68に上がります。

つまり、**何を「近い」とみなすかは、チャンネルに何を入れるかで決まります**。チャンネルの選び方が、そのまま「この街の住民は何を大事にして行動を選ぶのか」という世界観になります。だから、チャンネルは思いつきで決めてはいけません。

## チャンネルはどう作られるのか

調べると、チャンネル（特徴の軸）の作り方には大きく4系統ありました。

| 系統 | 例 | 良い点 | 弱い点 |
|---|---|---|---|
| 人が決める | ゲームのステータス、推薦のジャンル | 軸に名前がある | 設計者が思いつかない軸は入らない |
| データから学ぶ | word2vec、CLIP、協調フィルタリング | 思いつかない軸も拾える | 軸に名前がない |
| 人の感覚から測る | CIE Lab 色空間、距離学習 | 人間の「近さ」に合う | 大量の比較実験が要る |
| 多数の候補を少数にまとめる | 性格の Big Five（因子分析） | 軸が結果として見つかり、名前も付けられる | 採点データが要る |

面白いのは色です。RGBは機械の都合の空間ですが、人間にとっての色の近さを表す CIE Lab は、人に色を見比べてもらう実験から作られました。最初のたとえの RGB は、実はこの話につながっていました。

ゲームの世界では、**軸に名前があり、世界の反応とつながっている**ことが大事です。そこで MESA では、チャンネルを2種類に分けました。

- **基本の7チャンネル（人が決める）:** 満腹・休息・日用品・楽しさ・治療・務め・用事。空腹・疲労などの既存の状態と直結していて、「世界がどう反応するか」がはっきりしているので、統計で探す必要がありません。
- **暮らしのチャンネル（因子分析で見つける）:** 「人と過ごしたい」「新しいものを見たい」のような、状態としてはまだ持っていない欲求です。これを Big Five と同じ作り方で見つけます。

## 因子分析で「暮らし」の軸を見つける

手順は性格の Big Five と同じです。

1. 過ごし方を40個書き出す（犬の散歩・動物園・図書館で読書・サッカー・知らない街を歩く…）
2. 記述を14個用意する（人と話す・大勢・ひとり・静か・くつろぐ・屋外・緑や生き物・汗をかく・知らない場所・初めての体験…）
3. 40 × 14 の表を 0〜1 で採点する（初版は LLM が採点）
4. 記述どうしの相関行列を作り、固有値分解する
5. 固有値が1を超える因子を残し（カイザー基準）、バリマックス回転で軸を読みやすくする
6. 各因子に強く効く記述を見て、名前を付ける

ライブラリは使わず、ヤコビ法の固有値分解とバリマックス回転を JS で書きました（100行ほどです）。結果はこうなりました。

```
固有値: 4.51 3.01 2.82 1.52 | 0.84 0.43 …   → 固有値 > 1 の因子 4 つ

因子1  ひとり-0.90 騒がしい+0.89 大勢+0.87 人と話す+0.83 静か-0.81
       → 人と会う   (飲み会 / 祭り / ライブ / カラオケ)
因子2  体力を使う+0.96 汗をかく+0.91 くつろぐ-0.86
       → 体を動かす (サッカー / ボルダリング / 筋トレ)
因子3  初めての体験+0.95 知らない場所+0.90 非日常+0.78 学べる+0.73
       → 新しさ     (旅行 / 知らない街を歩く / 路地裏探検)
因子4  屋外+0.89 緑や生き物+0.88
       → 自然       (登山 / ガーデニング / 犬の散歩)
```

### 「静けさ」は出なかった

実は最初、**「静けさ」も軸にするつもりでした**。図書館や神社の価値を表すためです。ところが因子として出ませんでした。

- 「ひとり・静か」は、「人と会う」軸の**反対側**に吸収された
- 「くつろぐ」は、「体を動かす」軸の反対側に吸収された
- 因子を5つに固定しても、5つ目は「学べる」だけの弱い軸（固有値0.84）だった

「静か」は「人と会わない」ことの裏返しでしかなく、独立した軸ではなかった、ということです。**データに従って外しました。** 図書館の価値は、休息・楽しさ・新しさの組み合わせで表しています。

「軸は結果として見つかり、名前は後から付ける」という Big Five のやり方を真似た意味が、ここで出ました。自分で軸を決めていたら、「静けさ」を疑わずに入れていたはずです。

最終的なチャンネルは11個です（基本7 + 暮らし4）。

## 書くのは「世界」だけ

ここからが本題です。ベクトル化して一番変わったのは、**住民の行動の規則を書かなくなった**ことです。書くのは世界の側、つまり場所が何を与えてくれるかだけです。

```js
// vec.js — 場所の提供ベクトル (抜粋)
cafe:    { a: vec({ food: .45, rest: .5, social: .45 }),              open: [7, 21] },
park:    { a: vec({ nature: .9, rest: .4, active: .45, social: .3 }), open: null },
post:    { a: vec({ errand: 1.0 }),                                    open: [9, 17] },
library: { a: vec({ fun: .45, rest: .45, novelty: .45, errand: .15 }), open: [9, 20] },
```

開店時間は、閉店の前後30分でなめらかに提供が落ちるようにしました。境目の時刻に全員が一斉に店を出るのを防ぐためです。

### 時代は「自宅が与えるもの」だけで表す

前回の記事で入れた時代（アナログ → PC → スマホ → AI）は、**自宅の提供ベクトルを変える**だけで表しました。

```
              アナログ  PC    スマホ  AI
満腹            .25    .30    .45    .55     自炊 → 出前
日用品          0      0      .55    .75     通販
用事            0      .15    .70    .90     ネット銀行・電子申請
人と会う        .05    .10    .35    .45     電話 → SNS → 通話
務め (在宅可)   0      .10    .60    .95     在宅勤務
```

「スマホ時代は通販する」とは、どこにも書いていません。書いたのは「スマホ時代の自宅は日用品を0.55与える」だけです。住民は、遠くの店まで歩くのと、自宅で届くのを待つのを損得で比べて、自分で選びます。

### 結果: 規則を書かずに時代の差が出た

時代を固定して6日間回しました（1人あたりの人・秒、人口150）。

| | アナログ | PC | スマホ | AI |
|---|---|---|---|---|
| 朝に職場へ向かう | 29.9 | 33.5 | 22.5 | **0.8** |
| 通勤ピークの鋭さ | 0.19 | **0.24** | 0.22 | – |
| 在宅勤務 | 0 | 0 | 19 | **302** |
| 屋外の人流 | 766 | 722 | 592 | **385** |
| 通販（6日間） | 0 | 0 | 880 | 785 |

郵便局の用事は、アナログとPCの時代にだけ現れました（過ごし方の5.9%と4.2%）。スマホ以降は、家から手続きできるので郵便局へ行きません。

**在宅勤務のコードは1行も書いていません。** それでもAI時代には、朝の通勤がほぼ消えました。

## 欲求はなめらかな曲線で作る

「ロジックをなくす」には、欲求の側からも if を消す必要があります。欲求の強さは、状態のなめらかな関数にしました。

```js
food = 2.4·hunger² + 3·hunger⁸       // 限界に近いほど急に強くなる
rest = 1.8·fatigue² + 3·fatigue⁸ + 2.6·circadian(時刻, 時代の眠気の中心 + 個人差)
duty = sigmoid(始業) · sigmoid(終業) · (1.9 + 0.6·勤勉)
```

`hunger⁸` の項が、段の代わりです。空腹がほぼ限界になると、この項が仕事の欲求（最大2.5程度）を超えます。だから「腹ペコのまま働き続ける」は起きません。**優先順位を if で書かなくても、生命に関わる逆転は曲線の形で防げます。**

眠気の山の中心は時代で変えています（アナログ1:15 → スマホ3:15）。夜更かしも、規則ではなく曲線のずれです。

## 表せない行動を捨てない

照合してみても、欲求に合う場所が街のどこにも無いことがあります。これを捨てずに使います。

- **判定:** 一番強い欲求（務め・休息を除く）を、行ける範囲のどこでも満たせない
- **住民のつぶやき:** 「『用事』を満たせる場所が近くに無いなあ」
- **起業の需要:** 1日分の叶わなかった欲求ベクトルを溜め、一番合う建物の型を選び、その場所の起業の需要に足す

```
💭 住民の叶わなかった「満腹×治療」が溜まっている — 🍜 ラーメン屋 のような場所が求められている
```

住民の叶わない欲求が、新しい店を生む。現実の街で新しい業態が生まれる流れと同じ形です。

## 踏んだ罠

### 罠1: 居るだけで全部満たされる

最初は、その場所に居るだけで、提供ベクトルの全チャンネルが満たされる実装でした。

すると、自宅で眠っている間に空腹まで回復してしまいます（自宅は満腹0.45を与えるので）。**誰も朝食に出かけなくなり、来店が段の版の1/3に落ちました。**

直し方は「満たされるのは、その場所で**いましていること**のぶんだけ」です。選んだ行動の中でそのチャンネルが効いた割合を「集中度」とし、それに比例して満たします。寝ている人は休息が満たされ、空腹はほとんど満たされません。

### 罠2: 叶わなかった欲求が1日3万件

最初の判定は「選んだ場所で、欲求全体の3割以下しか満たされない」でした。複数の欲求を同時に持つ人は、どこへ行ってもこれに当てはまります。**1日3万件を超えて、意味のある信号になりませんでした。**

次に、判定を「一番強い欲求に応える場所が、行ける範囲のどこにも無い」だけに絞りました。それでも1日3〜4万件出ました。閉店後に「用事」を抱えた人が、**毎秒**数えられていたのです。最後に「1人1日1チャンネルにつき1回」にして、1日200件前後に落ち着きました。

叶わなかった欲求は、**数え方を間違えると全員がいつも不満を持っている街**になります。

## 旧ロジックとの比較（正直な結果）

同じ種で6日間回しました。

| | 段（if-else） | ベクトル |
|---|---|---|
| 飢えている人（空腹 > 0.97） | 16.4% | **7.3%** |
| 疲れ切った人 | 4.5% | 6.1% |
| 深夜に自宅 | 85.0% | 83.8% |
| 1日の過ごし方の種類 | 最大8 | **平均59.5** |
| **経済活動（来店の累計）** | **10074** | **5089** |

暮らしは健全になりました。飢えている人は半分以下で、過ごし方は7倍以上に増えました。

一方で、**来店が約半分に落ちました**。家で食事や娯楽を済ませる人が増え、用の無い時間に店へふらりと入らなくなったためです。MESA では来店の累計が街の発展段階を決めているので、**街の育つ速さが落ちます**（村になるのが6日目 → 9日目）。

段の版では、用事の無い住民は「ランダムな建物へ向かって歩く」ので、結果として店に入っていました。その「なんとなく店に入る」は、ベクトル版では損得に合わないので起きません。暮らしとしてはベクトル版のほうが自然ですが、街の経済としては、段の版のでたらめさに支えられていた部分があった、ということです。

ほかにも、AI時代は在宅勤務がほぼ全員になります（自宅の務め0.95と職場1.0の差が、移動の手間より小さいため）。規則で書いていた頃の80%より極端です。

## チャンネルは動的に変えるべきか

最後に、作りながら考えたことを書きます。「チャンネルは運用中に変わるものなのか」です。

世の中の例を見ると、**チャンネルの「種類」はめったに変えず、「値」は常に動かす**のが普通でした。

| 例 | 種類 | 値 |
|---|---|---|
| 色（RGB・CIE Lab） | 規格で固定 | ピクセルごとに毎フレーム |
| Big Five | 1990年代から5つのまま | 人ごと・年齢で変わる |
| 推薦の埋め込み | 次元は固定。学習し直すと全部入れ替わる | 利用のたびに更新 |

種類を変えると、保存データ・学習した方策・時代をまたいだ比較が全部ずれるからです。推薦システムが「数か月ごとに学習し直す」ときも、全部のベクトルをまとめて作り直し、バージョンを切り替えています。

MESA では、基本の7チャンネルは固定、暮らしのチャンネルは「末尾に足すだけ・バージョンを記録する」、値は常に動的、という3層で運用するつもりです。

そして1つ気づいたことがあります。**今の「叶わなかった欲求」では、新しいチャンネルは原理的に見つかりません。** 叶わなかった欲求も、既存のチャンネルの組み合わせで記録しているからです。既存の軸の外にある欲求を見つけるには、外から来る信号が要ります。たとえば LLM や視聴者が出した過ごし方の文章を採点表に足して、因子分析をやり直す、といった形です。

## まとめ

- 行動を、ラベルではなく**チャンネルの強さの組（ベクトル）**にした。場所も同じチャンネルで「何を与えるか」を持ち、照合で行き先を選ぶ。名前は後から付ける
- 1日の過ごし方は、最大8種類から平均59.5種類になった
- チャンネルは、世界の反応と直結する**基本7つを人が決め**、暮らしの**4つを因子分析で見つけた**。「静けさ」は軸として出なかったので外した
- 時代は**自宅の提供ベクトルを変えるだけ**で表した。在宅勤務・通販・郵便局の用事は、規則として1行も書いていないのに現れた
- 欲求は**なめらかな曲線**で作り、if の段を無くした。生命に関わる逆転は、曲線の形（`hunger⁸`）で防いだ
- ただし**来店が半分に落ちた**。段の版の「なんとなく店に入る」でたらめさが、街の経済を支えていた

次は、ベクトルを出力する方策としてハイポリシーを学習し直し、手で決めた欲求の曲線と、方策が自分で見つけた欲求を比べてみる予定です。

実装と実測値の全体は、リポジトリの `vec.js` と `docs/vec-actions-spec.md` にあります。
