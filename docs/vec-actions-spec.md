# 行動のベクトル化 — 仕様

住民の「いま何をするか」を、**行動の一覧から段の優先順位 (if-else) で選ぶのをやめた**。
代わりに、住民の**欲求ベクトル**と、場所が与える**提供ベクトル**を照合する。

```
住民の「したいこと」  d = [満腹 0.8, 休息 0.2, 人と会う 0.6, 自然 0.4, …]
場所の「できること」  A = [満腹 0.9, 人と会う 0.2, …]            (ラーメン屋)
選ぶ場所            = argmax  Σ_c w_c · d_c · A_c  −  移動の手間  +  行きつけ  +  揺らぎ
名前               = 選んだ後に付ける (「🌳 公園で体を動かす (誰かと一緒に)」)
```

RGB が 3 チャンネルの強さで無限の色を表すのと同じで、チャンネルは 11 個でも過ごし方は連続に作れる。

| ファイル | 役割 |
|---|---|
| `vec.js` | チャンネル、場所の提供ベクトル (時刻・時代つき)、欲求の曲線、照合、名前付け、叶わなかった欲求。**server.js に依存しない** |
| `server.js`「行動のベクトル化」節 | 4 つの入口 (needOf / pickLifeGoal / shouldLeaveBuilding / retargetOnNeedChange)、満たされ方 (stepNeeds)、叶わなかった欲求 → 起業、計測 |
| `data/vec/activities.json` | 暮らしのチャンネルを見つけるための採点表 (過ごし方 40 × 記述 14) |
| `tools/vec-channels.js` | 採点表の因子分析 (相関 → ヤコビ法 → カイザー基準 → バリマックス回転) |
| `tools/vec-report.js` | VEC=0 (段) と VEC=1 (ベクトル) を同じ種で並べる。`--eras` で時代ごとの人流 |

`VEC=0` で従来の段 (options.js + hlp.js) に戻る。**比較の基準として残してある**。

## 1. チャンネル (11)

| 種類 | チャンネル | 欲求の元 | 満たされ方 |
|---|---|---|---|
| 基本 | 満腹 | 空腹 `hunger` | `EAT_RECOVER × A_満腹` |
| 基本 | 休息 | 疲労 `fatigue` + 夜の眠気の山 | 自宅は `SLEEP_RECOVER`、他は仮眠 (`REST_FLOOR` まで) |
| 基本 | 日用品 | `supply` | `BUY_RECOVER × A` |
| 基本 | 楽しさ | 退屈 `bored` | `FUN_RECOVER × A` |
| 基本 | 治療 | 病気 `sick` | `SICK_HEAL × A` |
| 基本 | 務め | 勤務・通学の時間帯の曲線 (状態を持たない) | — |
| 基本 | 用事 | `a.vn.errand` (手紙・支払い) | `LIFE_SAT × A` |
| 暮らし | 人と会う / 新しさ / 自然 / 体を動かす | `a.vn.*` が時間で溜まる × 性格 | `LIFE_SAT × A` |

基本の 7 つは**世界の反応 (欲求の増減) と直結する**ので統計で探す必要がない。
暮らしの 4 つは因子分析で見つけた (§2)。**世界が反応しないチャンネルは置かない** (違う行動を生まないので)。

### 欲求はなめらかな曲線で作る (段の if を置かない)

```js
food = 2.4·hunger² + 3·hunger⁸       // 限界に近いほど急に強くなる → 腹ペコのまま働き続けない
rest = 1.8·fatigue² + 3·fatigue⁸ + 2.6·circadian(時刻, 時代の眠気の中心 + 個人差)
duty = sigmoid(始業) · sigmoid(終業) · (1.9 + 0.6·勤勉)
```

### 満たされるのは「いましていること」のぶんだけ

その場所に居るだけで全チャンネルが満たされる、にはしない。
**集中度 = 選んだ行動の中でそのチャンネルが効いた割合** (下限 0.15)。

> ★ 最初は居るだけで満たされていて、自宅で眠っている間に空腹まで回復し、誰も朝食に出かけなかった
> (来店が旧ロジックの 1/3 に落ちた)。集中度を入れて約 1/2 まで戻った。

## 2. 暮らしのチャンネルの見つけ方 (`node tools/vec-channels.js`)

性格の Big Five と同じ手順。過ごし方 40 個 × 記述 14 個を 0〜1 で採点し (初版は LLM が採点)、因子分析する。

```
固有値: 4.51 3.01 2.82 1.52 | 0.84 0.43 …   → 固有値 > 1 の因子 4 つ
因子1  ひとり-0.90 騒がしい+0.89 大勢+0.87 人と話す+0.83 静か-0.81   → 人と会う   (飲み会/祭り/ライブ/カラオケ)
因子2  体力を使う+0.96 汗をかく+0.91 くつろぐ-0.86                    → 体を動かす (サッカー/ボルダリング/筋トレ)
因子3  初めての体験+0.95 知らない場所+0.90 非日常+0.78 学べる+0.73      → 新しさ     (旅行/知らない街/路地裏探検)
因子4  屋外+0.89 緑や生き物+0.88                                         → 自然       (登山/ガーデニング/犬の散歩)
```

**「静けさ」は候補だったが因子として出なかった。** 「ひとり・静か」は人と会う軸の、「くつろぐ」は
体を動かす軸の反対側に吸収された。因子を 5 つに固定しても、5 つ目は「学べる」だけの弱い軸 (固有値 0.84) だった。
データに従って外し、静かな場所 (図書館・神社) の価値は 休息・新しさ・自然 で表している。

## 3. 場所の提供ベクトル

- 公開の建物 22 種: `vec.js` の `PLACE`。開店時間 (前後 0.5 時間でなめらかに) と出費感つき。
- 住宅・職場・学校は**本人だけ**: 自宅 / 職場 / 家なしの住居 (休息 0.8)。
- 街を歩く: 体を動かす 0.35 / 新しさ 0.25 / 自然 0.15 / 人と会う 0.1。

### 時代は「自宅が与えるもの」だけで表す

```
              アナログ  PC    スマホ  AI
休息            1.0    1.0    1.0    1.0
満腹            .25    .30    .45    .55     自炊 → 出前
楽しさ          .15    .25    .40    .50     ラジオ → ゲーム → 動画 → VR
日用品          0      0      .55    .75     通販
用事            0      .15    .70    .90     ネット銀行・電子申請
人と会う        .05    .10    .35    .45     電話 → SNS → 通話
務め (在宅可)   0      .10    .60    .95     在宅勤務
新しさ          0      .10    .20    .30
```

在宅勤務・通販・郵便局の用事・夜更かしは、**どこにも規則として書いていない**
(以前の `TECH_TELEWORK=80%` のような割合と、Option `errand` / `order-online` / `home-evening` は VEC=1 では使わない)。
眠気の山の中心だけは時代で変える (アナログ 1:15 → スマホ 3:15)。

## 4. 叶わなかった欲求を捨てない

- **判定**: いちばん強い欲求 (務め・休息を除く) を、行ける範囲のどこでも満たせない
  (その場所の提供 − 移動の手間 が 0.3 未満)。1 人 1 日 1 チャンネルにつき 1 回数える。
- 住民のつぶやき: 「『用事』を満たせる場所が近くに無いなあ」
- 日次: 溜まった欲求ベクトルに最も合う建物の型を選び、その場所の起業の需要に足す
  (`💭 住民の叶わなかった「満腹×治療」が溜まっている — 🍜 ラーメン屋 のような場所が求められている`)。
  型が 飲食/買い物/娯楽/医療 以外 (郵便局など) のときはログだけ。

> ★ 判定の作り直しは 2 回。①「選んだ場所で欲求全体の 3 割以下」→ 複数の欲求を持つ人は常に該当して 1 日 3 万件。
> ② 毎秒数える → 閉店後の「用事」だけで数万件。今は 1 日 200 件前後。

## 6. 分かっている問題

- **来店が段の版の約半分。** 住民が家で食事・娯楽を済ませ、用の無い時間に店へふらりと入らないため。
  街の発展段階 (経済活動の累計で決まる) の進みが遅くなる (村になるのが 6 → 9 日目)。
  暮らしとしては健全 (飢えが半分以下) だが、配信の「街が育つ」速さは落ちる。
- **AI 時代は在宅勤務がほぼ全員**になる (自宅の務め 0.95 と職場 1.0 の差が移動の手間より小さい)。
  規則で書いていた頃 (80%) より極端。自宅の務めを下げるか、職場に「人と会う」を強めると緩む。
- 郵便局・銀行の叶わなかった「用事」は起業の需要に回らない (郵便局は住民が起業する店の分類に無い)。
- ポリシーモード: 学習した `hlp.onnx` は VEC=1 では使わない (起動時に警告)。
  ベクトルを出力する方策として学習し直すのは未着手 (欲求ベクトルの計算を方策に置き換える口として `vecDesire` を分けてある)。

## 7. つまみ

```bash
VEC=0            # 従来の段に戻す (比較の基準)
VEC_EVERY=7      # 何 tick に 1 回、選び直しを計算するか
VEC_JITTER=0.08  # 人と日による好みの揺らぎ
VEC_FAM=0.25     # 行きつけの効き
VEC_DEBUG=1      # 13 時と 19 時に行き先の種類と欲求の平均を出す / =labels で名前の実例も
```

照合の重み・移動の手間・欲求の曲線・場所の提供ベクトルは `vec.js` の定数。
