24時間配信している街のシミュレーション（[MESA](https://github.com/oggata/mesa-clouds-renderer)）に、「時代」を入れました。アナログ → パソコン → スマホ → AI と進み、AI時代にタイムマシンを発明すると1980年に戻って2周目が始まります。

きっかけは Valheim の「銅 → スズ → 青銅」の技術ツリーと、Age of Empires の「暗黒時代 → 封建時代」でした。これを現代に置き換えて、**時代が進むと住民の暮らし方そのものが変わる街**を作りたかったのです。

作ってみて一番大事だった判断は、**住民の意思決定の「どの層」を時代で変えるか**でした。この記事はその話です。

- 「いま何をするか」を決める**ハイポリシー**は、時代で変える
- 「どう歩くか」を決める**ローポリシー**は、時代で変えない
- そして時代の差は、**課題を簡単にするのではなく、住民の道具を進化させる**ことで作る

うまくいった部分と、まだ届いていない部分（学習した方策がロジックに負けた時代がある）の両方を、実測値つきで書きます。

## 前提: MESA の住民は二層で動いている

MESA の住民は、意思決定が2層に分かれています。

```
ハイポリシー (低頻度)   「いま何をするか」
  入力: 性格 / 空腹・疲労などの欲求 / 時刻 / 記憶 / 街の状態
  出力: Option ひとつ (「飲食カテゴリの店へ行く」「帰って寝る」…)
        ↓
ローポリシー (毎tick)   「それをどう実行するか」
  入力: 一人称の視覚 (DINOv2) / 経路 / 周囲の人と車
  出力: 前進 / 左 / 右
```

ハイポリシーは手書きの効用（ロジックモード）でも、学習した `hlp.onnx`（ポリシーモード）でも動きます。ローポリシーは、歩行の方策か pure pursuit です。

## 時代で変えるのはどちらの層か

最初に決めたのはこれです。

**ローポリシーは時代で変えません。** 車を避ける、歩道を歩く、建物を目で見分ける。こうした能力は1980年でも2025年でも同じはずです。ここを時代で変えると、学習済みの歩行モデルを時代ごとに作り直すことになります。しかも、そうする理由がありません。

**変わるのはハイポリシーです。** スマホがあれば買い物に出かけなくていい。AIがあれば通勤しなくていい。変わるのは「どこへ行くか・行かないか」の損得で、歩き方ではありません。

この線を引いたことで、実装の範囲がはっきりしました。時代の効果はすべて「Option の選択肢」「その条件」「効用」に入れます。ローポリシーの観測・行動・学習済みモデルには、1ビットも触りません。

## 研究: 時代を進める課題は「ヒット&ブロー」

時代は住民の発見で進みます。時代ごとに3段の発明（トランジスタ → マイコン → パソコン、など）があり、1段ごとに隠れた正解が1つあります。

```
〈素材〉 × 〈場所〉 × 〈試す人の特性〉 × 〈時間帯〉   6 × 5 × 4 × 4 = 480 通り
 シリコン   自宅のガレージ   理系          朝
 銅線       学び舎           夜型          夜 …
```

住民は仮説を1つ選び、その場所へ歩いて、その時間帯に実験します。結果は「いくつ当たったか（0〜4）」**だけ**が掲示板に貼られます。

特性の欄は「実験した本人の特性」なので、自分では試せない仮説があります。そういう仮説は「次は『夜型』の人に、仕事場×磁石×夜を試してほしい」という依頼として貼られます。住民が手分けして答えを探す形です。

## 決定1: 難易度は全時代で同じ（PoW のように）

最初の実装では、時代の長さを揃えることを優先していました。AI時代に研究が早く終わっても、「普及待ち」の期間で時間を埋めて、どの時代も同じ長さにしていたのです。

これは間違いでした。**時代ごとに住民が違う最適化をしても、画面上は同じ長さに見える**からです。住民が賢くなったことが、どこにも現れません。

そこで方針を変えました。ブロックチェーンの Proof of Work と同じで、**課題の難易度は一定、解く側が速くなる**形にします。

- 全時代で同じもの: 480通り、3段、素材6個とその湧き方、1日に実験できる回数、期限
- 時代で変わるもの: 住民の側の**道具**だけ

住民が早く解けば、時代は早く進みます。

## 決定2: 時代は「情報の伝わり方」と「推論の強さ」を進化させる

では、道具の差をどう作るか。時代ごとに2つの軸を持たせました。

```js
// tech.js
const ERA_SHARE = ['gossip', 'visit', 'live', 'live'];   // 情報の伝わり方
const ERA_INFER = ['folk',   'folk',  'folk', 'logic'];  // 推論の強さ
```

| 時代 | 情報の伝わり方 | 推論 | 探索としての意味 |
|---|---|---|---|
| アナログ | すれ違った人とだけ、知っている結果を交換 | 民間の知恵 | 局所的で遅い。同じ実験が街中で重複する |
| PC | 図書館・市役所へ行けば全員の投稿が読める | 民間の知恵 | 中央集権。読みに行くコストがある |
| スマホ | どこでも読める。誰が何を試しているかも見える | 民間の知恵 | 重複が消える |
| AI | どこでも読める | 候補を論理的に絞り込む | 二分探索が効く |

「民間の知恵」は、AI以前の住民の推論です。

- 試した組み合わせは避ける
- 「0個当たり」だった結果に含まれる要素は避ける
- 当たりの多かった結果に似た組み合わせを試す

AI時代の住民だけが、掲示板の全結果と矛盾しない候補を論理的に列挙し、結果が一番よく割れる仮説（エントロピー最大）を選びます。

もう1つ効いたのが、**住民ごとに「知っている結果の集合」を持たせた**ことです。最初は「掲示板を何件目まで読んだか」を1つの数で持っていました。しかしアナログ時代は、すれ違った人から聞いた結果だけを知っているので、知識が歯抜けになります。集合で持つようにして、初めて「アナログは遅い」が再現されました。

### 結果: 同じ課題でも、時代で解く速さが変わった

絵の無い抽象シミュレーションで、1段の発明までにかかった実験回数を測りました（住民6人、同時に3人が実験、200回の平均）。

| 時代 | 1段あたりの実験回数 |
|---|---|
| アナログ | 47.3回 |
| PC | 26.0回 |
| スマホ | 18.7回 |
| AI | 10.8回 |

課題は同じなので、この差はすべて住民の道具の差です。

実際の街で早送りした結果も並べます（日数の目盛りを1/4に縮めた設定、研究にかかった日数 / 試した組み合わせ数）。

| | アナログ | PC | スマホ | AI |
|---|---|---|---|---|
| 1周目 | 10日 / 57 | 5日 / 40 | 4日 / 48 | 2日 / 17 |
| 2周目 | 9日 / 102 | 13日 / 56 | 7日 / 57 | 3日 / 21 |
| 掲示板なし | 10日 / 57 | 10日 / 98 | 10日 / 94 | 4日 / 23 |

2周目では PC がアナログより遅くなっています。種によるばらつきは大きく、きれいな単調減少にはなりません。

一方で、**掲示板を無効にすると PC とスマホの利点が消える**のははっきり出ました。抽象シミュレーションでも、共有なしだと実験は約26回、いつでも読めると約11回です。選び方の賢さ（ランダム ↔ 二分木）を変えても、差はほとんど出ませんでした。**賢さより共有**、というのは作る前に想像していなかった結果です。

## 研究のポリシー: 学習した方策はロジックに勝てたか

研究の「どの仮説を試すか」には、ポリシーモードもあります。候補ごとに20個の特徴量を作り、小さなMLP（20→16→1）でスコアを付け、softmaxで選びます。

特徴量の例は、結果の割れ方・歩く遠さ・時間帯までの待ち・依頼か・当たりの多かった結果との似かた、などです。

配信サーバーではONNXを回さない制約があるので、推論は素のJSで回る大きさにしました。**学習もNodeで回します。** 学習と本番が同じ `tech.js` の特徴量を呼ぶので、「学習時と本番で観測の定義がズレる」事故が構造的に起きません。以前、ハイポリシーをノートブックで学習したときに、通行判定が学習側と本番側で反転していたことがありました。その反省です。

学習は2段階です。

1. **模倣**: その時代のロジックの選び方を真似る
2. **強化**: REINFORCE + Adam。コスト = 街の時間 + 実験1回×8時間

ゼロからREINFORCEを始めた版は、民間の知恵にすら届きませんでした（アナログでコスト673 対 ロジック429）。また、時間だけを報酬にすると、実験回数を多く使ってしまい、本番（1日の実験数に上限がある）ではかえって遅くなりました。実験回数そのものが、一番きつい資源だったのです。

学習に使っていない種での検証結果です（実験回数 / 時間 / コスト）。

| 時代 | ロジック | ポリシー |
|---|---|---|
| アナログ | 42.0 / 93h / 429 | 46.6 / 108h / **481** |
| PC | 23.2 / 64h / 249 | 24.2 / 59h / **253** |
| スマホ | 17.8 / 49h / 191 | 18.2 / 45h / **190** |
| AI | 9.4 / 52h / 127 | 9.9 / 30h / **109** |

**スマホとAIではポリシーが勝ちました。** 特にAI時代は、ほぼ同じ実験回数で時間を4割短くしています。二分木は「回数」の最適化で、歩く遠さや時間帯の待ちを見ていません。方策はそこを埋めました。

**アナログとPCでは、民間の知恵に1〜12%負けています。** 検証結果は不合格の印（`passed=false`）を付けたまま置いてあり、ポリシーモードで起動すると警告が出ます。既定はロジックモードです。

時代ごとに見ると、**ポリシーが勝ちやすいのは情報がよく共有される時代**でした。アナログのように情報が歯抜けな時代で、民間の知恵を超える選び方を見つけるには、まだ何か足りていません（観測に「誰から聞いたか」を入れる、など）。

## 人流: ハイポリシーの選択肢と条件を時代で変える

研究とは別に、時代は住民の1日の過ごし方も変えます。ここがこの記事の本題の、ハイポリシーの最適化です。

| 時代 | 人流の性格 | 効かせた場所 |
|---|---|---|
| アナログ | 全部歩く。郵便局・銀行へ用事。早寝早起き。始業が人によってバラバラ | Option `errand`、睡眠の時刻、始業のずれ |
| PC | 始業が9時にそろい、通勤ピークが鋭い | 始業のずれ = 0 |
| スマホ | 買い物は通販。夜更かしだが夜は家でスマホ | Option `order-online` / `home-evening` |
| AI | ほとんど在宅勤務。通勤が消える | 在宅勤務の日は職場の代わりに自宅へ |

MESA のハイポリシーは、行動を Option というデータで持っています。**行動を1つ増やすのは `register()` を1回呼ぶだけ**です。

```js
// options.js — スマホ/AI時代の「通販で注文する」
{
  id: 'order-online', need: 'order', tier: TIER.errand + 10,
  text: 'order daily supplies online from home instead of going to a shop',
  precond: (a, C) => C.era != null && C.era >= 2 && !!a.home
    && (a.supply || 0) > C.thr.needHi && !!(C.ordersOnline && C.ordersOnline(a)),
  target: () => spec('home'),
  stay: (a, C) => C.indoorsAt(a, a.home[0], a.home[1]),
}
```

時代の行動は、時代の機能がオンのときだけ登録します。**機能を切った状態では、選択肢も条件も既存と1ビットも変わらない**ことを2通りで確かめました。

- 関数の総当たり: 選択48万通り、行き先2万通りで不一致0
- 同じ種で街を回したときの状態のハッシュ: 改造前と一致

オフィスは取り壊しません。AI時代にオフィスが空いても、効くのは通勤だけです。通販は近くの商店への注文として売上に数えるので、人流が変わっても店が連鎖的に潰れることはありません。

### 結果: 時代で人流が変わった

時代を固定して6日間回し、1人あたりの「人・秒」で測りました（人口約130）。

| | アナログ | PC | スマホ | AI |
|---|---|---|---|---|
| 朝7〜10時に職場へ向かう | 22.1 | 22.0 | 17.2 | **4.7** |
| 通勤の総量 | 81 | 83 | 57 | **18** |
| 通勤ピークの鋭さ（最混雑1時間の割合） | 0.13 | **0.20** | 0.17 | 0.15 |
| 屋外に居た総量 | 931 | 960 | **823** | **839** |
| 店で買う / 通販 | 86 / 0 | 96 / 0 | 30 / 96 | 14 / 100 |

PC時代は通勤ピークが一番鋭くなりました。スマホ時代は買い物が通販に置き換わり、屋外の人流が減りました。AI時代は、朝の通勤が1/5になりました。

### 計測で踏んだ罠: 在宅勤務なのに通勤が減らない

最初の計測では、AI時代でも通勤がほとんど減っていませんでした（アナログ140 → AI 143）。在宅勤務80%の時代です。

調べると、2つの問題が重なっていました。

1. **実装の問題。** 在宅勤務の人も7時に起きて外へ出かけ、9時の始業で**自宅へ歩いて帰っていました**。行き先は自宅ですが、欲求は「勤務」なので、外を歩いて家に向かう人が生まれていました。在宅勤務の日は、起きた時刻にそのまま家で仕事を始めるように直しました。
2. **計測の問題。** 「欲求が勤務の人が屋外にいる」を通勤として数えていました。在宅勤務の人が外から家へ帰る道のりも、通勤に入っていたのです。**行き先が職場の人だけ**を数えるように直しました。

直すと、通勤の総量はアナログ81 → AI 18になりました。以前、ホテリングの法則を実装したときも同じでしたが、「効いていない」ように見えるとき、原因の半分は計測側にあります。

## 正直な注記: ロジックモードの人流は、まだ「規則」で書いている

ここは誤解のないように書いておきます。

上の人流の変化は、**ロジックモードのハイポリシーに時代ごとの選択肢と条件を与えた結果**です。「AI時代は80%が在宅勤務」「スマホ時代は70%が通販派」という割合は、手で決めています。住民が損得を比べて自分で選んだ結果ではありません。

「時代ごとに住民が違う最適化を辿る」を本当に実現するのは、**ポリシーモードのハイポリシー**の役目です。そのための準備までは済ませました。

- 学習用の抽象都市を差し替え、観測の末尾に「時代 one-hot 4 + 今日の用事の有無 1」を足した
- 行動に `errand` / `order-online` / `telework` を足し、寝る時刻と選べる行動を時代で変えた
- **報酬の式は変えていない。** 違う1日は、移動時間・お金・欲求の損得から出てくるはず
- 検証セルでは、同じ方策を4つの時代で回して行動の割合を並べる。「アナログで用事が出ない」「スマホで通販が店を置き換えない」「AIで在宅が通勤を上回らない」のどれかなら配備しない
- サーバー側は、モデルのメタに時代の次元があるときだけ観測に時代を足す。既存の学習済みモデルはそのまま動く。ダミーモデル（観測51次元・行動26種）で配線を確認済み

**学習はまだ回していません**（手元に torch が無く、Colab 待ちです）。回して、規則で書いた人流と方策が自分で見つけた人流を並べるのが、次の記事になる予定です。

## 配信のための約束: 研究を絶対に止めない

24時間配信なので、「研究が止まって何も起きない時間」は致命的です。研究が止まる理由を洗い出し、それぞれに打開策を用意しました。

| 止まる理由 | 打開策 |
|---|---|
| 研究に要る建物が無い | 街が建てる → 建たなければ仮設の研究所で代用 |
| 正解の特性を持つ人がいない | 誰かが独学で身につける |
| 前進が無い | 用事がある人も手伝う → ひらめき（正解の欄を1つ明かす）＋行商人が素材を届ける |
| 答えが絞れたのに誰も試しに行かない | 条件に合う人を優先して送り出す |
| それでも期限 | 試行錯誤の末に / 偶然の大発見 |

1つ気をつけたことがあります。「答えが3通りに絞れた」と論理的に分かるのは、AI時代の住民だけです。アナログ時代に、街が答えの分かる人を優先して送り出すと、**住民が知らないはずの答えを街が使う**ことになり、時代で難易度が変わってしまいます。この打開策は、AI時代か、行き詰まりが深いときだけ使うようにしました。

わざと詰まる状況を作って検証しました（素材に誰も気づかない / 実験に出られない / 掲示板なし / ポリシーモード）。すべての筋書きで期限内に時代が進み、偶然の大発見は0回、前進の無い日は最長1日でした。

## 視聴者に見せる

最後に画面です。左上の1枚に、時代・研究の進み・前の時代の記録をまとめました。

```
6日目 18:13
人口 24  集落  晴れ
アナログ時代 1984年  研究 33%
[トランジスタ] › [マイコン] › [パソコン]
素材  ◆◆◆◇◇◇ 3/6
試した5通り · すれ違った人にだけ伝わる
●○○○ 見張りマティアス(夜型) 飲食店×乾電池×夕方
実験中: 記録魔コウ、野心家ハルオ
記録 アナログ10日/57通り  PC5日/40通り
```

「残り○通り」の絞り込みバーは、AI時代にだけ出ます。アナログ時代には「試した数」と「どう伝わるか」を出します。**住民の道具が時代で違うことを、画面でも見せる**ためです。「記録」の行には、同じ課題を前の時代に何日で解いたかが並びます。

屋上の小物も時代で変わります。アナログはテレビアンテナ、PCはパラボラ、スマホは基地局、AIは太陽光パネルとドローンです。ここも見た目だけで、ローポリシーの観測（レイキャスタ）には出していません。

## まとめ

- 時代で変えるのは**ハイポリシー**（何をするか）で、**ローポリシー**（どう歩くか）は変えない。この線を引くと、学習済みの歩行モデルに触らずに済む
- 時代の差は、課題を簡単にするのではなく、**住民の道具（情報の伝わり方と推論の強さ）**を進化させて作る。難易度を一定にしたことで、「住民が賢くなった」が研究の日数として見えるようになった
- 同じ課題でも、1段あたりの実験回数はアナログ47回 → AI 11回。効いたのは推論の賢さより**共有**だった
- 学習した方策は、情報がよく共有される時代（スマホ・AI）ではロジックに勝ち、アナログ・PCでは負けた
- 人流は時代で変わった（AIで朝の通勤が1/5）。ただしロジックモードでは規則として書いている。「方策が自分で時代ごとの1日を見つける」は、ハイポリシーの再学習待ち

実装と実測値の全体は、リポジトリの `docs/tech-era-spec.md` にあります。
