# 時代と研究開発 — 仕様

街に「時代」の軸を足す。**アナログ → パソコン → スマホ → AI → (タイムマシンで) アナログ 2 周目**。

- 発展段階 (集落→都市) は**大きさ**の軸で、経済で上がる。時代は**発見**で上がる。
- **課題の難易度は全時代で同じ** (ブロックチェーンの PoW と同じ)。住民が速く解けば時代は速く進む。
  速さの差は「情報の伝わり方」と「推論の強さ」、つまり**住民の側の道具**からだけ生まれる。
- 時代は「いま何をするか」(ハイポリシー) の損得も変える。歩き方・車の回避・視覚 (ローポリシー) は変えない。

| ファイル | 役割 |
|---|---|
| `tech.js` | 時代・研究の定義、ヒット&ブロー、時代ごとの共有と推論、特徴量、選び方、抽象シミュレーション。**server.js に依存しない** |
| `server.js` の「時代と研究開発」節 | 研究者の状態機械、行き詰まりの解消、時代の人流、HUD、3D、`/tech` |
| `options.js` | 時代の行動 (`registerEraOptions`)、時代つきメタの読み込み (`registerFromMeta`) |
| `tools/tech-sim.js` | 時代ごとに同じ課題がどれだけ速く解けるか (ロジック / ポリシー) |
| `tools/tech-train.js` | 研究の方策の学習 (模倣 → 強化、Node だけ) → `data/tech_policy.json` |
| `tools/tech-report.js` | 早送りで「研究が止まらずに時代が進むか」を筋書きごとに検査 |
| ノートブック セル E2 / G2 | ハイポリシーに時代を入れる env と、時代ごとに違う 1 日になったかの検証 |

## 1. 研究 = ヒット&ブロー (全時代で同じ課題)

時代ごとに**3 段の発明**がある (銅→スズ→青銅 のように)。段ごとに隠れた正解が 1 つ。

| 時代へ | 1 段目 | 2 段目 | 3 段目 (時代を変える) |
|---|---|---|---|
| パソコン | トランジスタ | マイコン | パソコン |
| スマホ | 携帯電話 | インターネット | スマートフォン |
| AI | 検索エンジン | ディープラーニング | 人工知能 |
| 2 周目 | 量子コンピュータ | 時空理論 | タイムマシン |

正解は **〈素材〉×〈場所〉×〈試す人の特性〉×〈時間帯〉= 6×5×4×4 = 480 通り**。

- 素材は街に湧く (光る水晶 + 光の柱)。住民が近くを通って気づくまで実験に使えない。
- 特性の欄は**実験した本人の特性**。自分で試せない仮説は「次は『夜型』の人に…」と依頼として貼られる。
- 結果は「いくつ当たったか (0〜4)」**だけ**。
- 段 j の正解の素材は「湧く順番の 2j 番目か 2j+1 番目」— 新しい素材が見つかって初めて次の発明に届く。
- **全時代で同じもの**: 480 通り / 3 段 / 素材 6 個と湧き方 (`TECH_SPAWN_DAYS`) / 1 日の実験数 (`TECH_EXP_PER_DAY`) / 期限。

## 2. 時代が情報共有と推論を進化させる

| 時代 | 共有 (`ERA_SHARE`) | 推論 (`ERA_INFER`) | 探索としての意味 |
|---|---|---|---|
| アナログ | **gossip** すれ違った人と、知っている結果を交換する | **folk** 民間の知恵 | 局所的・遅い。同じ実験が街中で重複する |
| PC | **visit** 図書館・市役所・学び舎へ行けば全員の投稿が読める。研究者は先に寄る | folk | 中央集権。読みに行くコストがある |
| スマホ | **live** どこでも読める。「いま誰が何を試しているか」も見える | folk | 重複が消える |
| AI | live | **logic** 全結果と矛盾しない候補に論理的に絞り、二分木で選ぶ | 二分探索が効く。HUD に「残り○通り」が出る |

- **民間の知恵 (folk)**: 試した組み合わせと「0 個当たり」の結果に含まれる要素を避け、
  当たりの多かった結果に似た組み合わせを試す (`Σ(当たり-1)×共有する要素`)。矛盾する候補も残る。
- 住民ごとに**知っている結果の集合**を持つ (アナログは歯抜けになる)。
- 答えが論理的に絞れたときの「終盤モード」(該当者を優先して送る) は **AI 時代だけ**。
  それ以前の時代では、住民が知らないはずの答えへ街が人を送ることになるため、行き詰まり Lv2 まで使わない。

### 実測 (`node tools/tech-sim.js --n=200`, 住民 6 人・同時 3 人、1 段あたり)

| 時代 | ロジック 実験 / 時間 |
|---|---|
| アナログ | **47.3 回** / 59h |
| PC | **26.0 回** / 39h |
| スマホ | **18.7 回** / 29h |
| AI | **10.8 回** / 37h |

本番では 1 日の実験数に上限があるので、**実験回数がそのまま時代の長さの差**になる。
つまみ (`tech.js`): `GOSSIP_P=0.05` (すれ違いで交換する確率) / `VISIT_P=0.3` / `FOLK_NOISE=4`。

## 3. ロジックモードとポリシーモード (研究の仮説選び)

| | 選び方 |
|---|---|
| ロジック (既定) | その時代の推論 (AI 以前は民間の知恵、AI は二分木) |
| ポリシー (`TECH_MODE=policy`) | 20→16→1 の MLP で候補ごとにスコア → softmax。`data/tech_policy.json` |

特徴量 (20): 候補に入っているか / 割れ方のエントロピー / 最悪の残り割合 / 正解確率 / 残り候補数 /
依頼か / 視聴者のアイデアか / 歩く遠さ / 時間帯までの待ち / 素材・場所・特性がどれだけ試されたか /
自分の特性は正解に無いと分かっているか / 時代 one-hot / 掲示板の既読率 / バイアス /
**当たりの多かった結果との似かた**。候補の集合 S は時代の推論で作る (AI 以前は民間の知恵の集合)。

### 学習 (`node tools/tech-train.js --episodes=12000 --bc=3000 --lr=0.001 --temp=0.3`)

1. **模倣**: その時代のロジックの選び方を真似る (ゼロからの REINFORCE は民間の知恵にすら届かなかった)
2. **強化**: REINFORCE + Adam。コスト = 街の時間 + 実験 1 回 × 8 時間 (本番では実験の回数が一番きつい資源)

学習に使っていない種での検証 (実験回数 / 時間 / コスト):

| 時代 | ロジック | ポリシー |
|---|---|---|
| アナログ | 42.0 / 93h / 429 | 46.6 / 108h / **481** |
| PC | 23.2 / 64h / 249 | 24.2 / 59h / **253** |
| スマホ | 17.8 / 49h / 191 | 18.2 / 45h / **190** |
| AI | 9.4 / 52h / 127 | 9.9 / 30h / **109** |

**正直な結果**: スマホと AI ではポリシーがロジックに勝つ (AI は時間を 4 割短縮)。
アナログと PC では民間の知恵に 1〜12% 負ける — `validation.passed=false` のまま配っているので、
`TECH_MODE=policy` で起動すると警告が出る。既定はロジック。

## 4. 時代が人流 (ハイポリシー) を変える

> **2026-09-15 更新**: 既定 (VEC=1) では、この節の「規則」(在宅勤務の割合・Option `errand` / `order-online` /
> `home-evening`) は使わない。時代は**自宅が与えるベクトル**だけで表し、人流は照合の結果として出る。
> 仕様と実測は `docs/vec-actions-spec.md`。以下は VEC=0 (規則版) の記録として残す。

オフィスは**取り壊さない**。効くのは通勤だけ。

| 時代 | 人流の性格 | 効かせた場所 |
|---|---|---|
| アナログ | 全部歩く。郵便局・銀行が現役。早寝早起き (21〜5:30 時)。始業が人によってバラバラ | Option `errand` (その日に用事がある人 35%)、`options.js` sleep の `C.sleepFrom/wakeAt`、work の `C.workShift` (±1.5h) |
| PC | 始業が 9 時に揃う = 通勤ピークが鋭い。用事は少し残る (15%) | `workShift=0` |
| スマホ | 買い物は通販 (70%)。夜更かし (23:30〜7 時)。夜は家でスマホ (50%)。在宅勤務 25%。配達員 2 倍 | Option `order-online` / `home-evening`、`stepNeeds` の自宅での日用品回復、`TECH_TELEWORK`、`TECH_CREW` |
| AI | 在宅勤務 80% (起きたらそのまま家で始める)。通販 90%。配達員 3 倍 | 同上 |

- 時代の行動は `TECH=1` のときだけ登録する。**TECH=0 では選択肢も条件も既存と同一** (hlp-equiv 48 万通り一致)。
- 通販は近くの商店への注文として**売上と来店数に数える** (人流が変わっても店が連鎖閉店しないように)。
  注文した家は配達員が優先して回る。

### 実測 (`TECH_START_ERA` を固定、人口約 130、6 日、1 人あたりの人・秒)

| | アナログ | PC | スマホ | AI |
|---|---|---|---|---|
| 朝 7-10 時に職場へ向かう | 22.1 | 22.0 | 17.2 | **4.7** |
| 通勤の総量 | 81 | 83 | 57 | **18** |
| 通勤ピークの鋭さ (最混雑 1 時間の割合) | 0.13 | **0.20** | 0.17 | 0.15 |
| 屋外に居た総量 | 931 | 960 | **823** | **839** |
| 店で買う / 通販 | 86 / 0 | 96 / 0 | 30 / 96 | 14 / 100 |
| 郵便局・銀行の用事 | 7 | 4 | – | – |
| 配達された荷物 (6 日) | 10 | – | – | 21 |

- 「通勤」は**職場へ向かっている**人だけを数える。在宅勤務の人が朝食から自宅へ帰る道のりを含めると、
  AI 時代でも通勤が減らないように見えた (計測の誤り)。
- 郵便局の用事は少ない (勤めている人は仕事の後にしか行けない)。

### ポリシーモードのハイポリシー (ノートブック セル E2 / G2、要 Colab 再学習)

- **E2**: `HighLevelCityEnv` を `EraCityEnv` に差し替える。観測の末尾に 時代 one-hot 4 + 今日の用事 1、
  行動に `errand` / `order-online` / `telework` を足し、寝る時刻と選べる行動を時代で変える。
  **報酬の式は変えない** — 違う 1 日は損得 (移動時間・お金・欲求) から出てくるはず。
- **G2**: 同じ方策を 4 時代で回し、通勤・在宅・店・通販・用事の割合を並べる。
  アナログで errand が出ない / スマホで通販が店を置き換えない / AI で在宅が通勤を上回らない、
  のどれかなら配備しない。`hlp_meta.json` に `era_dim=5` と行動の `eras` を書き足す。
- server.js は `era_dim` があるときだけ観測に時代を足す (既存の `hlp.onnx` はそのまま動く)。
  `node tools/make-dummy-hlp.js --era` で配線を確認済み (観測 51 次元・行動 26 種で推論が回る)。
- **学習はまだ回していない** (torch が無いため)。

## 5. 行き詰まりの解消 — 配信を止めない

| # | 止まる理由 | 打開策 |
|---|---|---|
| ① | 研究に要る建物が無い | 1 日待って街が建てる → 3 日で建たなければ仮設の研究所で免除 |
| ② | 正解の特性を持つ人が居ない | 誰かが独学で身につける (AI 時代は候補が 3 通り以下になったら待たない) |
| ③ | 正解の場所が街に無い | 街が建てる |
| ④ | 前進が無い (`TECH_STALL_DAYS`) | Lv1 用事があっても手伝う + 素材の光が強くなる / Lv2 ひらめき (正解の欄を 1 つ明かす) + 行商人 |
| ⑤ | 答えが絞れているのに誰も試しに行かない | 終盤モード (AI 時代、または Lv2 以上) |
| ⑥ | それでも期限 | 段の期限 (`TECH_STEP_DAYS`, 段の開始から) で「試行錯誤の末に」/ 時代の期限 (`TECH_MAX_DAYS`) で偶然の大発見 |

期限と行き詰まりの日数は**全時代で同じ**。

## 7. 視聴者 (左上は 3 行だけ、中身は右下のカード)

左上の日付板は 3 行だけ。研究の中身まで積むと街が隠れるので、**進捗があったときだけ**右下にカードを出す。

```
6日目 18:13
人口 24  集落  晴れ
アナログ時代 1984年  研究 33%
```

右下のカード (`techCardRows` / `updateTechCard`):

```
研究: パソコンへの道                     新しい結果   ← なぜ出たか
[トランジスタ] › [マイコン] › [パソコン]              済=緑 / いま=金枠 / まだ=灰
  素材    場所    人     時間
 [ ? ]  [ ? ]  [夜型]  [ ? ]   答え                  ← ひらめき / AI 時代は論理で決まった欄が埋まる
 [磁石] [自宅] [夜型]  [昼 ]   ●○○○                ← 直近 3 件 (新しいものが上、緑枠)
 [乾電池][自宅] [理系]  [朝 ]   ○○○○
右の丸＝合っている欄の数 (どの欄かは分からない)
素材 3/6 · 光る場所の近くを通ると見つかる
 [銅線] [乾電池] [磁石] / [ ? ] [ ? ] [ ? ]           ← 湧く順。後ろの段の正解ほど後から湧く
伝わる ●━━━━━━━━  口コミ 5%                        ← 住民が平均して結果の何割を知っているか
推理 勘 (似た組み合わせを試す) · 試した2/480通り      ← AI 時代は「絞込 ━━━ 残り78通り」のバー
実験中: 記録魔コウ、野心家ハルオ…                      ← 次にやること (依頼・ひらめき・行き詰まり)
記録 アナログ10日/57通り  PC5日/40通り
```

- 出るきっかけ: 実験の結果 / 素材の発見 / ひらめき / 発明 / 研究の開始 / 行き詰まり / 研究所ができた / 時代の交代。
  数が減っただけ (段が変わって掲示板がまっさらになった等) では出さない。チャットの `!tech` でも出る。
- `TECH_CARD_SEC` 秒 (実時間、既定 20) で消える。0 なら出しっぱなし。出ている間に進捗があれば延長する。
- 年号は研究の進み具合で進める (時代の長さが住民しだいで変わるため)。
- バナーは画面上の中央。チャット: `!idea 銅線 学び舎 夜` / `!tech`。`/tech` に `records` (時代ごとの記録)。

## 8. 検証

```bash
TECH=0 …                              # 既存の指紋と一致 (seed=12345 3日 → 2abaad5c)
node tools/hlp-equiv.js               # 選択 48万 / 行き先 2万 不一致 0
node tools/pastime-report.js          # 時代の娯楽を含む全項目が選ばれる
node tools/tech-sim.js                # 時代ごとの研究の速さ
node tools/tech-train.js              # 研究の方策 (模倣 → 強化)
node tools/tech-report.js             # 筋書き (normal / no-find / no-hands / no-board / policy)
```

### tech-report の実測 (`--days=70 --scale=0.25 --seeds=1`、筋書きごとに並列)

5 本すべて合格 (偶然の大発見 0 回、前進の無い日は最長 1 日)。**課題は同じ**で、研究にかかった日数と試した組み合わせ:

| 筋書き | アナログ | PC | スマホ | AI | 備考 |
|---|---|---|---|---|---|
| normal (1 周目) | 10日 / 57 | 5日 / 40 | 4日 / 48 | **2日 / 17** | 8 回の時代交代 |
| normal (2 周目) | 9日 / 102 | 13日 / 56 | 7日 / 57 | 3日 / 21 | 種によって PC がアナログより遅い周もある |
| no-board (掲示板なし) | 10日 / 57 | 10日 / 98 | 10日 / 94 | 4日 / 23 | 共有が無いと PC・スマホの利点が消える |
| no-find (素材に気づかない) | 11日 | 8日 | 8日 | 10日 | 行商人とひらめき (22 回) で進む |
| policy | 16日 / 98 | 9日 / 56 | 8日 / 71 | 6日 / 18 | アナログはロジックより遅い (§3 と同じ傾向) |

- `--scale=0.25` なので 1 日の実験数は 8 回、行き詰まり判定は 1 日 (本番は 2 回 / 5 日)。ひらめきは本番より出やすい。
- 1 周 (4 時代) は normal でおよそ 21〜36 日 (scale 0.25)。本番の日数に直すと住民の速さしだいで変わる — **3 日で 1 周の保証はもう無い**。

## 9. つまみ

```bash
TECH=0                  # 丸ごと切る (既存と同一の指紋)
TECH_MODE=policy        # 学習した方策で仮説を選ぶ
TECH_START_ERA=0..3     # 始める時代
TECH_LOOP=0             # AI 時代で止める (タイムマシンを研究しない)
TECH_BOARD=0            # 掲示板を読まない (比較実験)
TECH_PANEL=0            # 右下の研究カードを出さない (左上の時代と研究 % は残る)
TECH_CARD_SEC=20        # 研究カードを出しておく秒数 (実時間)。0 = 出しっぱなし
TECH_DAY_SCALE=1        # 研究の日数をまとめて縮める (検証用。課題の中身は変わらない)
TECH_QUIET_DAYS=2 TECH_SPAWN_DAYS=10 TECH_STEP_DAYS=45 TECH_MAX_DAYS=150 TECH_STALL_DAYS=5
TECH_EXP_PER_DAY=2 TECH_MAX_ACTIVE=3 TECH_FIND_P TECH_FIND_R TECH_REMOTE_GOSSIP
```

保存: `city_state.json` の `tech`。街のリセット (POP_MAX) でも技術は受け継ぐ。
